# Security audit — November 2026 (Junid, 23 Nov 2026)

Live probe of marathon-club (store app main 395ef0a8, POS e9b864b6). Produced by
`scripts/security/access-matrix.mjs`: reads are probed LIVE with real tokens and
bounded (`orderBy="$key"&limitToFirst=1`, body discarded); writes are evaluated by
loading the LIVE rules into the RTDB emulator (the real rules engine) — nothing was
written to real data. Every probe account was deleted and confirmed gone by an owner
lookup.

Personas: **stranger** = an email/password account anyone can create with the public
web key; **strangerG** = a Google account with no `/users` record; **anon** = an
anonymous session (every TV board); **staff** = a real active cashier.

## Auth settings found

- Client sign-up: **open** (email/password and Google). Anonymous: on.
- Project is plain Firebase Auth, not Identity Platform: blocking functions are not
  available without an irreversible upgrade.
- 224 accounts: 171 anonymous, 39 staff (password, all with `/users` records),
  2 owners (Google), **10 Google accounts with no staff record**, 1 leftover test
  password account.
